# Known issues

- 当前已使用 xAPIC/IOAPIC，但 timer 仍来自 PIT；没有 LAPIC timer、TSC-deadline、MSI/MSI-X、interrupt affinity 或 application processor 启动。
- IDT 已有关键 exception diagnostic gate，但 double fault 仍没有独立 IST，page fault 只能诊断并停止，不能 demand-page。
- executor 固定为三个 task，没有 spawn、task ownership、cancellation 或 timer wheel。
- framebuffer 渲染是全屏重绘，没有 damage tracking、double buffering 或 virtio-gpu。
- 三个 surface 已使用 niri 式 tiled strip + floating layer。tile 支持 normal/tabbed stack、gap-aware resize/preset/maximize/center/expand、固定与方向 consume/expel、focus/reorder；floating window 始终在 tile 上方，可切层焦点、方向移动、resize、跨 workspace move、标题栏拖动和 pointer resize，并接受有序 `open-floating true|false` rule。限制是 tile→float 只从当前屏幕 rect 推导有界尺寸，float→tile 按当前 focus 邻近插入；尚无父子窗/固定尺寸自动浮动、跨重启位置记忆、精确 `default-floating-position`、自由边缘 resize、tab 点击/拖曳或动画。edge maximize 与 column maximize 是独立状态，stack focused window edge-maximize 后不会自动并回。另有容量 4 的动态 workspace、最多 64 项 bind 和有序 `app-id` rule。PID 2 已跨 reload 常驻，但 compositor、surface、配置 bank 与 renderer 仍在 ring 0；没有 Wayland client、任意数量 workspace、multi-output、完整 rule/action、overview 或通用 IPC。
- niri KDL、Waybar JSONC/CSS 与 swww environment 已按 user/system/fallback 路径从 root VFS 加载，支持显式原子 reload 和 parse-before-swap rollback；`/sbin/slop-shell` 会在 4096/512-byte 上限内流式读取系统 Waybar/swww 文件，以 40-byte commit 连续提交实际文件摘要，并通过 32-byte policy/config event 跨 generation 休眠与恢复。独立 QEMU 回归验证了非默认 1300-byte Waybar JSONC，但没有普通配置编辑器、文件 watcher/inotify、per-user session 或通用跨进程配置服务。顶部栏已有常用 module normal/alternate format、format-alt-click、受限左/右/中键与上下滚轮 action、颜色/box/border CSS 子集，CPU/Memory 初值来自用户态 snapshot，其他 provider 仍固定；没有真实 polling、Pango、完整 GTK CSS、smooth-scroll threshold、POSIX shell 或 per-output。swww 风格状态机支持纯色 clear 与最多 8 KiB 的 root VFS P3/PNM path load；双 bank 会在完整动画后才释放旧图，missing/invalid 文件保留当前图。限制是相对路径固定相对 `/usr/share/slopos` 且由大写终端规范化为小写、不同尺寸图片的 transition 回退为 `none`；没有独立常驻 IPC/layer-shell process、PNG/JPEG/GIF、animated image、无界缓存、多 output 或精确帧时序。
- `initrd.slp` 仍不是文件系统；独立 ext4 disk 已有 fd 原位写与严格单块 EOF append/truncate、最多八 tag 的 active JBD2 transaction、block/inode allocation、线性目录 create→fd open→unlink 和启动时 replay。PID 1 已能用 `O_RDONLY`/`O_RDWR openat`、read/write/lseek/close 进入这条异步路径，但 scanner 当前只接受零 feature、单个非 wrap transaction；用户 mutation 只覆盖已分配 regular-file block，尚无通用 namespace syscall、多块或非连续 growth、revoke、多 transaction、通用权限或 btrfs。
- 已有 frame allocator、自有 early page table、bump heap、容量 4 的 process table、每 slot fd table，以及从 root `/sbin/slop-init`、`/sbin/slop-shell` 读取后经各自 Linux initial stack 与 `SYSCALL/SYSRETQ` 运行的 PID 1/2 user address space；文件 syscall 可按 PID 保存/恢复 frame、转为 Blocked 并异步等待 block Future，`sched_yield` 会 cooperative round-robin，100 Hz PIT 则会保存完整 CPL3 interrupt frame并切换两个独立 CR3。read/write copy 已验证跨两个 virtual stack page 和两个独立 physical frame。PID 1 当前常驻 blocked `wait4`，PID 2 常驻 desktop event，因此两套 page table/code/stack 由 runtime 保留；exit/reap、zombie/immediate 与每进程 7-frame 回收仍由 process 状态机和宿主测试覆盖。当前仍强制 init 的单 `PT_LOAD` ELF 与 BootInfo 引导副本相同，user copy 限于一页 code/两页 stack 和 256 bytes，也没有任意路径 exec、独立 thread/kernel stack、kernel preemption、SMP run queue、通用 wait selector/options/orphan adoption、广泛 VFS syscall或通用 mapping 回收。
- kernel 仍使用 2 MiB RWX identity huge page；PID 1 的 private page table 已隔离 supervisor kernel map，并区分 user read-only code 与 user-writable stack，但尚未施加 NX、完整 W^X 或细粒度 kernel section 权限。
- 当前内核固定加载到物理 64 MiB；切换自有页表前的最早期初始化仍依赖 OVMF 留下的 identity mapping。
- ACPI 当前解析 RSDP、RSDT/XSDT 和 MADT；尚未解析 MCFG、HPET、FADT，固定容量 parser 上限也不是完整 ACPICA 实现。
- PCI 使用 configuration mechanism 1 并消费 firmware 已分配 BAR；尚未解析 bridge 拓扑或 MCFG，也没有 BAR sizing/resource allocation、MSI/MSI-X 或电源管理。
- virtio-blk 当前有两个固定请求槽，已验证双块 read prefetch、单块 write、flush 和 cache invalidation。仍无通用 descriptor free list、任意生产者并发、discard/write-zeroes、writeback、timeout 或错误恢复。
- bitmap font 只覆盖 UI 使用的 ASCII 子集。
- `capture-desktop.sh` 使用 QEMU PPM；只有安装 `pnmtopng` 时才同时生成 PNG。
